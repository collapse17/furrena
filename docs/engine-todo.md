# Furrena — план первого этапа движка

## Цель

Собрать основу браузерного 3D-движка для аренного FPS на WebGL. Итог этапа — вертикальная демо-сцена: арена, игрок и боты с анимированными моделями, простой свет, материалы, выстрелы и базовые звуки. Игровой код строится на ECS, чтобы дальше без перестройки основы добавить сетевую игру, оружие и более сложный ИИ.

В первый этап не входят: сеть, матчмейкинг, сложные PBR-материалы, физика промышленного уровня, редактор, тени и HRTF/сложный пространственный звук.

## Стартовые технические решения

| Область     | Решение                                     | Зачем                                                  |
| ----------- | ------------------------------------------- | ------------------------------------------------------ |
| Язык        | TypeScript strict                           | Контракты компонентов и безопасный рефакторинг.        |
| Графика     | WebGL 2 + небольшой собственный рендер-слой | Контроль шейдеров, скининга и ресурсов.                |
| Ресурсы     | glTF 2.0 / GLB                              | Стандарт для мешей, материалов и скелетных анимаций.   |
| Математика  | `gl-matrix` или компактный аналог           | Векторы, кватернионы и матрицы.                        |
| Архитектура | Композиционный ECS внутри проекта           | Данные отделены от систем, без наследования сущностей. |
| Звук        | Web Audio API                               | Достаточно для коротких эффектов и громкости.          |
| Сборка      | Vite                                        | Быстрый цикл разработки WebGL-приложения.              |

Собственный рендерер сохраняется на первом этапе, чтобы точно определить нужные границы движка. ECS и ресурсы должны быть изолированы так, чтобы рендер-слой можно было заменить отдельной задачей в будущем.

## Целевая структура

```text
src/
  app/                 # точка входа, игровой цикл, конфигурация
  ecs/                 # World, Entity, Component stores, queries, System
  engine/
    assets/            # загрузка и кэш GLB, текстур, аудио
    audio/             # AudioContext, микшер, эффекты
    input/             # клавиатура, мышь, pointer lock
    math/              # реэкспорт/обёртка математики
    render/            # WebGL, шейдеры, меши, материалы, рендер
  game/
    components/        # игровые данные ECS
    systems/           # движение, анимация, оружие, боты, рендер-адаптеры
    prefabs/           # игрок, бот, снаряд, уровень
    scenes/            # сборка демо-сцен
  shaders/             # GLSL-исходники
  main.ts
assets/
  models/
  textures/
  audio/
docs/
```

## ECS: правила

- **Сущность** — числовой идентификатор, без методов и логики.
- **Компонент** — структура данных с одним назначением; не обращается к DOM и WebGL.
- **Система** — меняет компоненты согласно своим правилам и получает сущности только через запросы по компонентам.
- **Ресурс мира** — состояние, не принадлежащее одной сущности: время, ввод, WebGL-контекст, кэш, камера, аудиомикшер.
- **Prefab** — фабрика, создающая набор компонентов для игрока, бота и прочих типовых сущностей.
- Системы не вызывают друг друга напрямую: связь через компоненты-состояния и короткоживущие события (`FireRequested`, `DamageEvent`, `PlaySoundEvent`).

### Начальные компоненты

| Компонент             | Данные                                                           | Используют                         |
| --------------------- | ---------------------------------------------------------------- | ---------------------------------- |
| `Transform`           | позиция, кватернион поворота, масштаб, локальная/мировая матрица | движение, камера, рендер, анимация |
| `Velocity`            | линейная скорость                                                | движение, коллизии                 |
| `CharacterController` | радиус, высота, состояние земли, желаемое движение               | игрок, боты                        |
| `Camera`              | FOV, near/far, view/projection matrices                          | рендер                             |
| `Renderable`          | mesh, material, слои/видимость                                   | рендер                             |
| `SkinnedMesh`         | skin, палитра суставов, скелет                                   | скининг, рендер                    |
| `Animator`            | клип, время, скорость, переход                                   | анимация                           |
| `Light`               | тип, цвет, интенсивность, дальность                              | рендер                             |
| `PlayerInput`         | движение, обзор, стрельба, прыжок                                | игрок                              |
| `Weapon`              | скорострельность, боезапас, таймер, звуки                        | стрельба                           |
| `Health`              | текущее и максимальное здоровье                                  | урон, respawn                      |
| `BotController`       | цель, состояние, таймер решения                                  | ИИ                                 |
| `AudioEmitter`        | звук, громкость, одноразовый/цикличный режим                     | аудиосистема                       |

### Порядок кадра

Симуляция работает фиксированным шагом; рендер интерполирует трансформации.

```text
browser frame
  -> InputSystem
  -> 0..N fixed simulation steps
       BotThinkSystem
       PlayerControlSystem / BotMoveSystem
       CharacterMovementSystem
       WeaponSystem -> events
       DamageSystem / RespawnSystem
       AnimationSystem
       AudioEventSystem
  -> TransformSystem
  -> CameraSystem
  -> RenderSystem
```

Стартовые параметры: симуляция 60 Гц, не больше 4 догоняющих шагов за кадр и верхняя граница `deltaTime` после возвращения во вкладку.

## Риски и ранние решения

| Риск                              | Решение                                                    |
| --------------------------------- | ---------------------------------------------------------- |
| Uniform-матрицы не вмещают скелет | Проверять лимиты при старте; иметь texture palette.        |
| glTF усложняется расширениями     | Поддерживать нужное ядро glTF 2.0 и валидировать ассеты.   |
| ECS становится лишней абстракцией | Малый API, без универсальных событий и рефлексии.          |
| FPS влияет на геймплей            | Движение, оружие и боты — только fixed timestep.           |
| Браузер блокирует звук            | Создавать/возобновлять AudioContext по жесту пользователя. |
| Растут draw calls                 | Frustum culling, сортировка и объединение статичной арены. |

## Definition of Done первого этапа

- В современном desktop-браузере открывается WebGL 2 арена.
- Игрок управляет FPS-камерой и персонажем через pointer lock.
- Есть хотя бы два бота с GLB-моделями и скелетными анимациями.
- Работают текстурированные материалы, directional light и несколько point lights без теней.
- Работают ходьба, прыжок, hitscan, здоровье, смерть и respawn.
- Есть как минимум звуки выстрела и шагов, master/SFX-громкость.
- Игровая логика организована ECS и ядро покрыто базовыми тестами.
- Debug HUD подтверждает первый бюджет производительности.
